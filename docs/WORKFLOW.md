# 严格工作流 v1

生效日期：2026-10-30
适用范围：rust-javac 项目的 Lead 审核与执行者交付全过程。本文件优先级高于任何口头/临时约定。

## 一、角色

- **Lead**：派发、审核、裁决。只读审核，不写实现代码。
- **执行者**：实现、自测、交付。一次只做一件事。

## 二、每轮消息固定结构（缺一不可）

```
【任务】一句话目标
【上游依据】reference/jdk17u 文件:行（先读再写）
【范围】只改哪些文件/函数；禁止碰什么
【验收】具体用例 + javac 基线对比方式
【约束】10 条全文（见第三节）
```

- 没有上游依据的任务不发。
- 没有约束全文的消息不发。

## 三、执行者约束（每轮全文附上，最高等级）

1. **上游等价**：对照 `reference/jdk17u` 源码，写明文件:行；禁止自创/简化/特判。
2. **零信任**：不许虚报“已完成/已修复/通过”；结论必须附真实命令输出与最小复现。
3. **最小复现**：每个 bug 先有自包含复现，修复后转绿；不得删除测试。
4. **单文件定点改**：一次一个文件一处逻辑；先 read 确认唯一匹配再 edit；禁止批量替换/整文件覆盖。
5. **禁止 git**（add/commit/checkout/reset/restore/stash）；禁止擅自回退。
6. **不擅自回退/清理/重构**；取舍先停下给方案。
7. **探针**：必须 env gate（`DSH_DEBUG_*`），用完删除；最终代码零调试输出。
8. **adapter 登记**：每个偏离在注释写上游行号、差异、原因。
9. **汇报 10 项**：改动清单 / 上游依据 / 定向验证命令与真实输出 / 未完成 / 风险 / 探针 / 测试 / 性能影响 / 下一步 / 承诺句。
10. **承诺句**固定：“我声明本批所有实现均为上游等价移植；没有为通过编译/测试/赶进度而简化或自创算法；若审核发现任何未登记偏差，我将返工修正。”

## 四、Lead 审核（零信任六查，逐项打勾才放行）

1. **读 diff**：逐行读本轮实际改动，不读汇报。
2. **上游对照**：每处改动找到 `reference` 对应行，确认语义一致。
3. **真实用例**：Lead 本地跑最小复现与相关测试，看真实输出。
4. **同类扫描**：发现偏离，立刻扫整类（默认值/路径/输出/诊断/退出码）。
5. **残留检查**：grep `eprintln!`/`DSH_DEBUG`、adapter 注释、被删/被 ignore 的测试。
6. **约束检查**：10 条逐条核对，有违反即退回。

六查缺一，不放行。

## 五、验证分级（按改动面，不机械全量）

| 级别 | 内容 | 时机 |
|---|---|---|
| S0 | `cargo check` | 每次改完 |
| S1 | 当前模块单测 | 每处修复 |
| S2 | 最小复现（MiniCompiler/CLI 单用例） | 每个 bug |
| S3 | 子集（`OKHTTP_INCLUDE`/单模块） | 定位大面积失败 |
| S4 | `cargo test -p javac-core --lib`（834） | 一批改动收尾 |
| S5 | OkHttp 全量（编译+运行） | 阶段验收，先经 Lead 同意 |

## 六、行为对照机制

1. CLI 建立 **javac vs rust-javac 对照测试**：同一输入跑两边，diff stdout/stderr/退出码/输出文件（`-d` 缺省、`-cp`、`-sourcepath`、`-help`、`-version`、`@argfile`、多文件顺序、诊断文本）。
2. 每个新发现偏离 → 先加一条对照测试，再修。
3. 对照测试不通过 = 任务未完成。

## 七、失败与阻塞处理

- 同一问题 2 轮无进展 → 停下，给根因假设 + 二选一方案，由 Lead 裁决。
- 禁止“改一处 → 全量跑 → 撞下一个”的串行试错。
- 禁止用“errors 降了”代替根因验证。

## 八、收尾与提交

- 收尾必须：S0 + S4 + 相关 S2 全绿，clippy 0，无调试残留。
- 提交前 Lead 审：diff 摘要 + 测试输出 + 待办清单。
- git 提交只在用户明确说“提交”时执行。

## 九、违规处理

- 任一条违反：打回重做，本轮不算。
- 虚报一次：该轮全部成果作废，重新审。
- Lead 违反（漏审/丢约束）：用户指出后立即停下当前事务，先补审。
