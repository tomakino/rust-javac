# 工程标准（工业级）

> 本文件是项目的唯一工程标准。每轮交付必须对照执行；会话压缩后以本文件为准，不依赖任何人的记忆。

## 1. 性能预算（硬指标）

| 操作 | P95 预算 |
|---|---|
| definition / hover / typeDefinition | < 10ms |
| completion（含排序） | < 30ms |
| inlay hints / semantic tokens（可视区） | < 20ms |
| references / rename prepare | < 50ms |
| documentSymbol / folding / documentLink | < 10ms |
| selectionRange | < 5ms |
| codeAction | < 30ms |
| 单文件诊断（编辑后） | < 100ms |
| 全项目诊断（后台） | < 1s |
| 索引增量（单文件 + 依赖闭包） | < 50ms |
| 索引冷构建（81 文件，后台） | < 1s |
| 缓存加载 | < 100ms |

**超过即失败。** 每次交付附改前/改后实测数据。

## 2. 架构红线（出现即打回）

1. **AST-first**：语法/语义判断必须来自编译器 AST、DocTree 或 scanner token；禁止对源码文本做语法解析。
2. **禁止文本兜底**：`find('(')`、`find(';')`、`find("import")`、`strip_prefix("import")`、`char_indices` 扫描、`is_identifier_char`、手写词法，一律禁止。
3. **SSOT**：一个概念只有一处实现；发现第二套即合并。
4. **单一查询入口**：所有 LSP 功能走 `resolve_symbol`（位置/来源/文档/签名），禁止索引与 AST 双路径各自实现。
5. **按文件失效**：缓存失效粒度是文件 + 依赖闭包，禁止全局清空。
6. **失败返回空**：定位失败返回 `None`，禁止 fallback 到类声明等近似位置。
7. **无兼容代码**：项目未发布，旧 API/旧缓存/旧配置直接删除，不留 adapter。

## 3. 编辑流要求

- 编辑只更新文本（<1ms），诊断/分析防抖 150–300ms 并放后台。
- 旧请求按 `version`/`generation` 取消，不阻塞新请求。
- 分析使用增量编译（复用上下文），禁止每次 `rebuild()` 整个编译器。
- 索引增量按**声明变化**触发；方法体/注释改动不重索引。

## 4. 审核清单（每轮交付逐项打勾）

- [ ] 新增代码逐行读过，能指出每处 AST 依据（节点/字段）
- [ ] 红线扫描 0 命中
- [ ] 性能实测（改前/改后），是否在预算内
- [ ] 真实场景验证（Gson 项目、真实点击位置），不只用自造 fixture
- [ ] 编辑流验证（didOpen → didChange → 查询）
- [ ] 竞态验证（索引 Building 中、首次请求）
- [ ] 失败行为验证（无源码、无索引、重载歧义）
- [ ] 全量 + e2e 通过
- [ ] 差距清单已更新
- [ ] 未修改 `crates/javac-core`

## 6. 交付格式（每轮必须包含）

1. **改动**：文件、AST 依据
2. **性能**：改前/改后实测
3. **验证**：真实请求结果、测试输出
4. **红线扫描**：0 命中
5. **差距更新**：消除/新增
6. **未验证项**：如实列出

## 7. 测试要求

- 先写失败测试，再实现。
- 每个功能覆盖：成功、无源码、重载/泛型、编辑流、索引 Building、取消。
- 断言完整行为（逐段/逐字符），禁止「非空」「包含」弱断言。
- flaky 测试必须定位根因并修复，不许重跑掩盖。

## 8. 禁止事项

- 禁止修改 `crates/javac-core`（只读、只包装）。
- 禁止特判、简化、玩具实现。
- 禁止把「测试绿」当正确。
- 禁止把架构缺陷写成「剩余简化」。
- 禁止在未查证的情况下断言事实。
